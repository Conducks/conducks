# todo25 — close the audit: trust boundary, real gates, honest subprocesses
Status: todo
- Acceptance: no input reaches a shell or a file read unfiltered, and no gate in the suite can report clean without having checked the thing it names.

## Context

A five-dimension architecture audit (30 Jul 2026) plus this session's own tracing produced 49
findings. This todo carries the ones that change behaviour; the rest are recorded in `handover.md`
as known and accepted.

Read ADRs 0047, 0048 and 0049 first — they hold the decisions, and the phases below only implement
them. The audit's own verdict on the architecture was good and should not be lost in a list of
problems: one composition root, dependency direction genuinely held, and **zero static import
violations across 198 files**, verified independently. What follows is edge work, not a rebuild.

**Two findings are exploitable today and everything else can wait behind them.** Phase 1 is not
sequenced first for tidiness.

Phase order matters only where stated. Phases 1, 3, 4 and 5 touch disjoint files and can run at the
same time; Phase 2 must follow Phase 1 because both rewrite `chronicle-interface.ts`, and Phase 6
must follow Phase 4 because it triages what that gate reports.

## Phase 6 — triage the 458
- Depends: todo25#P4
- Builds: 0048
- [x] TRIAGED, and all 458 were the same false positive. They are one pair — UNIT → ECOSYSTEM — i.e. a file depending on an npm or node package. Canonical ranks are a CONTAINMENT ladder (ecosystem contains repository contains directory contains unit) and the rule read them as a DEPENDENCY ladder, so ECOSYSTEM's rank 0 made every `import path from 'node:path'` look like an abstract module depending on a concrete one. The rule now skips an ECOSYSTEM target, a genuine containment inversion still fires, and `guard` no longer carries a permanent findings line. Confirmed red against the rule's previous form. This is why the answer was triage rather than a ratchet: a ratchet would have frozen 458 false positives as the accepted baseline. `conducks guard` reported `rank_violations=458` as "pre-existing, tracked" and passed. A number carried as acceptable long enough stops being read. Sample 20, classify each as a real inversion or a rule artefact, and either fix the rule or set a ratchet the count may not exceed. Answers ADR 0048's open question

## Phase 7 — the two design questions carried from todo24
- [x] DECIDED and BUILT — ADR 0050. `nodes.pulseId` now means LAST seen for every row, which took one change: induction re-stamps the virtual nodes it used to skip, collected BY PROPERTY because a `lib::` node is never an edge target and a traversal-based re-stamp cannot reach it. A full pulse sweeps what it did not touch; the watcher must never call it, which the method name carries because the signature cannot. The whole-pulse test caught the traversal version deleting both library nodes on pulse two. Original framing: `pulseId` means FIRST seen, not last: two pulses into a clean vault there are 3,624 re-stamped nodes and 1,653 induced ones still carrying the pulse that created them, so deleting rows that are not the newest deletes every valid external symbol. Needs an ADR that says what identifies a live row before any sweep is written. Carried from todo24#P5
- [x] DECIDED and BUILT — ADR 0051. The source is now the PRODUCING CALL's target, recovered by matching the assignment's right-hand side against the calls in the same scope: `produce -> consume` instead of `value -> consume`, and dangling sources went to zero. When the producer cannot be recovered the edge is NOT written, because a dangling endpoint cannot be filtered by confidence the way a guess can. Original framing: a `PULSES_TO` edge's source is the variable name, not a node id, so 199 edges point from something the graph does not contain — and `audit` does not see it because its orphan check reads targets only. Options are the producing call's target, the enclosing scope, or a materialised local. Carried from todo24#P4
- [x] ANSWERED by ADR 0053, and BOTH options in the question were wrong.
