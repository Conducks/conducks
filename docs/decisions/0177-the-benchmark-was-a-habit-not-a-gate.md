# 0177 — the benchmark was a habit, not a gate
Status: Accepted
- Date: 2026-08-27
- Builds: 0175, 0176
- Enforced by: .git/hooks/pre-commit

## Context

`conducks-feature-clean` Rule 2 says a gate must FAIL on the thing it forbids, because *"a rule that
lives in a habit is a rule that is not kept"*. This repository wrote that rule and then broke it.

Measured: the pre-commit hook runs `docs-lint` and `visuals-lint`. There is no CI workflow. Neither
`bench:prune` — ten scenarios built one commit earlier — nor any of the seven oracles appears in any
gate. **All of it ran only when someone typed it.**

That is the exact shape the rule names: an instrument nobody runs automatically is an instrument that
stops running the week attention moves on, and its silence is indistinguishable from a pass.

## Decision

**`bench:prune` runs on commit, gated on the files that can change a prune answer** — the analyzer,
its contract, and the parsing layer that supplies its evidence.

It costs **7.9 seconds**, measured, which is the only reason a benchmark of ten analyzed repositories
belongs in a commit hook at all. The seven oracles do not: they re-analyze real subjects and take
minutes, so they live in `npm run gate`, one command that runs the build, the suite, the benchmark and
every oracle in order.

Written OUTSIDE the `>>> conducks gates` markers, because everything inside them is regenerated by
`conducks install-hooks` and an edit there is lost on the next run.

## Consequences

- Proved rather than assumed: with `ONLY_IMPORTED` mutated away and the analyzer staged, the hook
  exits **1** and names the failing scenario. Restored, it exits **0**.
- `npm run gate` is the documented before-shipping command. It did not exist; the sequence lived in
  this session's scrollback.

### Two rules this session did not keep, recorded rather than quietly fixed

- **Rule 16, cleaning is not fixing.** Commit `15ac466` removed 29 stale imports (a clean) AND
  changed which symbol `STALE_IMPORT` names AND repaired two oracle guards AND fixed flag parsing in
  four files — 28 files in one commit. The rule exists so a commit can say which change moved which
  number, and that one cannot. History is not rewritten; it is named here.
- **Rule 14, one unit per commit.** The same commit, for the same reason.

The rules kept, for the record, because a self-assessment that lists only failures is as useless as
one that lists only successes: Rule 6 (every change carries a measured why), Rule 8 (a `localName`
guard was written, failed mutation, and was deleted rather than kept), Rule 9 (`buildUsageIndex` was
hoisted rather than copied), Rule 10 (sixteen mutations run; one vacuous test deleted; two vacuous
benchmark scenarios strengthened), Rule 11 (the ten scenarios are the adversarial set), Rule 15 (the
suite and every oracle after each unit).
