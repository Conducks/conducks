9 · The pattern

The same shape appears at every altitude. A stage computes a correct result, and the step that would make the result observable is missing — not broken, absent. Virtual induction had no persist call. bindNeuralCircuits had no index update. micro-pulse had no guard on its success message. guard had no branch for "no data". The fallbackAnalysis field still has no writer. Each is one missing line, and each produces output that looks exactly like success.

Fixing them taught one more thing. PULSES_TO had a SECOND cause hiding behind the first: once the edges persisted, the capture that feeds them still never matched const x = f(). A fix that makes the count go from nothing to nothing is indistinguishable from no fix at all — so a repair is only finished when the store is counted, not when the code looks right.

That is why 660 passing tests coexisted with all of it: the tests assert that a stage ran, and every one of these stages does run. Nothing asserts that its output arrived — in the database, in the index, in the printed verdict. The single highest-value change on this page is not any individual fix; it is one test per stage that reads back what the stage claims to have written.
